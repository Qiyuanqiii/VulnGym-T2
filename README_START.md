# 先看这里：VulnGym T2 提交包

## Windows 64 位：解压后双击 start.cmd

请先将整个 ZIP 完整解压到你有写入权限的普通文件夹，再双击 `start.cmd`，不要在压缩软件内直接运行。
浏览器会自动打开本机工作台，直接查看历史结果、准备输入或开始实际提取；没有命令行设置菜单，不需要手填用量文件路径或历史请求数。
`start-extraction.cmd` 打开同一个完整工作台；`start-demo.cmd` 只打开历史结果回放。
包内附 CPython 3.13.12 便携运行时；查看演示不需要安装 Python、Git、Node，也不需要 API key。
如果浏览器没有自动打开，可复制启动窗口显示的 `http://127.0.0.1:端口` 地址到浏览器。
端口自动选择，不依赖原开发电脑；使用时保持启动窗口打开，结束时关闭该窗口即可。

## 选择资料下载的联网方式

- **`start.cmd`：系统默认。** 沿用当前网络配置；公告 HTTP 会遵循适用的环境/系统代理设置，Git 继续采用原有的受限下载配置。
- **`start-direct.cmd`：直连。** 公告和源码下载明确不使用代理。不修改 Windows 系统代理、环境变量或其他应用的网络设置。

两种方式都打开完整 Web 工作台，没有额外命令行配置问题。工作台显示当前资料联网方式；选择只对本次启动有效，不写入模型用量设置。要切换，请先让当前任务结束并关闭其启动窗口，再双击另一种启动文件；不要中断正在处理的任务。

直连适用于本机直连可访问公开服务、但代理出口不可用或匿名额度耗尽的情况。它不是“保证连通”开关：如果当前网络必须依赖代理，请使用 `start.cmd`。遇到 403、限流或连接失败时，只记录原错误，不自动换出口、切换来源或重试。

本选项只控制公开公告与源码获取；DeepSeek 模型连接方式、key 处理、费用上限与逐批确认均不改变。历史回放用 `start-demo.cmd`，仍不下载资料、不调用模型。

命令行等价入口为 `launch_workbench.py --network-mode system` 或 `launch_workbench.py --network-mode direct`；普通用户直接双击相应 CMD 即可。配置检查可在启动文件后加 `--check --no-browser`，不下载资料或调用模型。

**历史结果回放**是只读模式：可切换批次、查看依据、导出数据集/草稿/复核报告；不能发起模型请求，也不会创建或重置请求账本。
**完整工作台**默认不会发送模型请求或产生模型费用。准备资料、检查输入和查看保存结果不调用模型；只有在网页中输入自己的 key、设置本批次请求上限并明确同意后，才会开始实际提取。

## 演示顺序

本版已修正网页默认配置：low、多候选模式、本批默认上限 12 次；保留逐批确认和零自动重试。入口判断规则为 `snapshot-guidance-v85`：允许公告、同版本 API 文档、真实转发调用与方法、补丁相互印证的局部入口候选；不把文档前提冒充独立源码证明，名字猜测、证据冲突或缺少必要连接仍保留待补充。历史 v84 示例未改写，不能当成 v85 真实复测成绩；本次已完成相关离线回归与启动/免费检查，真实模型输出需在网页重新授权运行确认。

1. 先看 NLTK v84：一条字段完整的候选；右上角“导出数据集”得到 `entries.jsonl`。
2. 切换 SQL v83、Airflow v83：展示未知字段、草稿和依据；“更多文件”中导出 `drafts.jsonl`。
3. 打开 `demo/T2-demo.mp4` 查看约 1 分 21 秒的剪辑演示：本地资料输入、确认提取、查看依据和导出 `entries.jsonl`。视频已裁切画面并添加步骤字幕，等待段标注 8 倍速；原片音轨为静音，成片未添加配乐。本片展示本地资料输入，不是 URL 自动下载实测；视频内容不代替结果数据及其验证边界说明。
4. 想按视频重新操作，使用 [演示数据/NLTK](演示数据/NLTK/README.md)。其中附公告、补丁和可迁移的 `record.jsonl`，不含源码仓库；请按该说明准备本地 NLTK Git 仓库，在网页中填写仓库文件夹路径。实际提取还需自己的模型 key；只看视频和历史结果则不需要。

本包三个结果批次是已见开发案例，不是盲测或总体准确率证明。`verify=0`，完整候选也不表示人工确认。
已知读取和解释缺口见 `docs/t2_representative_validation_20260913.md` 及对应 NLTK/SQL/Airflow QA。
新增可选补读循环只有离线验证，未宣称真实增益。T1 自动反馈不在本次交付范围。

## 实际提取：在网页中确认，不会默认花费

需要 Git 已加入 PATH，以及你自己的有效模型 key。默认的链接输入按所选来源联网访问 GitHub 或 OSV，源码仓库仍从 GitHub 下载；使用本地资料时需要自行准备包含所需历史的 Git 仓库。

1. 双击 `start.cmd`，点击“添加资料并提取”，在默认的“粘贴公告链接（GHSA / OSV）”模式中一次粘贴一条或多条链接。支持换行、空格、Markdown 链接及混合来源，每批最多 20 条。OSV 页面和 API 的同一公告只处理一次；同一 GHSA 的 GitHub、OSV 链接作为不同来源保留，不会暗中合并。
2. 点击“获取资料并检查”：程序按链接所选来源下载公开公告，找到唯一可确定的公开源码仓库后下载 Git 历史；不需要填写仓库路径、公告缓存或映射文件。此阶段最多同时准备两份资料，不调用模型、不产生模型费用。限流、拒绝访问、下载超时或仓库不明确会显示为资料准备问题，不能当作提取成功。下载资料保存在解压目录的 `data/downloads`，后续可复用，不会自动删除。收到 GitHub 403 不会轮换 IP、自动改用 OSV 或重复请求。
3. 在网页中输入自己的模型 key，设置本批次最多允许的模型请求次数，阅读并确认授权后开始。每次授权仅适用于该批次；key 仅供当前使用，不会持久保存。请另外在模型服务平台设置自己的费用硬限额：网页中的请求次数上限不是人民币金额上限。

整个链接列表作为一个批次处理、共用一次请求上限；模型提取逐份进行，不会为每条链接同时启动一套付费任务。三份资料可把本批次上限设为 36 次（每份最多 12 次），不代表一定用满或一定产出三条完整结果。新链接入口的实现与验证边界见 [URL 批次说明](docs/t2_url_batch_20260914.md)。

OSV 示例：`https://osv.dev/vulnerability/GHSA-f8m6-h2c7-8h9x`；也接受 `https://api.osv.dev/v1/vulns/GHSA-f8m6-h2c7-8h9x`。这是用户直接选择的另一公开资料源，不是 GitHub 403 后的自动替代。OSV 原始内容与原始网址会保留；只有能够唯一关联 GHSA、明确标为 GitHub reviewed 并找到目标仓库的公告，才会准备为本题格式的输入。缺少这些依据时显示具体原因，不会把任意 OSV 公告伪装为经过 GitHub 审核的 GHSA 公告。

已有本地资料仍可切换输入方式：粘贴公告正文、上传资料，或选择本地批次文件。这两种方式保持离线，不自动下载。仓库路径要填 Git 仓库文件夹，不是 `record.jsonl`；本地 URL 列表文件需要缓存与仓库映射。公开示例在 `examples/t2_v2_input`，其中 `repos/...` 是占位路径。本包不内置第三方 Git 仓库。

程序自动在本机用户配置中保存累计用量，后续启动继续使用；换解压目录或换 key 不会清零。已有授权及历史累计使用量会由本机配置延续，不需要手动填写。请保留本机用量配置，不要删除或修改它来重置用量；程序也会检查累计请求上限。
提取结果保存在包内 `data/runs`，请保留 `data` 目录以便后续查找原始输出文件；它与本机累计用量配置是不同的存储位置。
只有默认链接模式会按所选 GitHub / OSV 来源自动获取公开公告，并获取其明确关联的 GitHub 仓库；所有模式均不运行目标代码。GUI 采用 low、多候选、每份资料最多 12 次请求；界面按识别的链接数建议本批上限，用户手动修改后不会自动调高，仍需逐批确认且不自动重试。现场结果不保证与旧批次一致，草稿不会被强制转为完整候选。

## 包内内容

- `start.cmd` / `start-extraction.cmd`：直接打开完整网页工作台；`start-demo.cmd`：免 key 的只读历史回放。
- `launch_workbench.py`：本地网页启动入口；`configure_launch.py`：保留的高级兼容工具，日常使用不需要运行。
- `runtime/python`：Windows x64 CPython 便携运行时与许可证，不含第三方 site-packages。
- `vulngym_t2`：完整产品源码与本地网页/图标/字体资源。
- `examples/run-01..03`：SQL v83、Airflow v83、NLTK v84 的完整公开结果及过程记录。
- `examples/t2_v2_input`：公开输入示例，需要另配目标源码仓库。
- `演示数据/NLTK`：与视频对应的输入资料和逐步使用说明；不含源码仓库、密钥或预填的提取答案，不依赖开发电脑路径。
- `docs/T2-design.pdf`：三页设计说明；该稿早于新增可选循环，最新边界另见补充文档。
- `demo/T2-demo.mp4`：用户确认采用的剪辑版演示，1920×1200、30 帧/秒；打包阶段原样收录成片，不再次转码。实际路径、输入文件名、字节数和 SHA-256 见 `SUBMISSION.json` 的 `demo_video`；其中 `transcoded` 指打包阶段是否转码，不表示视频未经剪辑。
- `ENGINEERING_README.md` / `docs` / `tests`：工程说明、开发过程、验证记录与离线测试源码。
- `SUBMISSION.json`：本次归档清单及版本/平台信息。

无密钥、原计费账本、原开发机器的本地用量配置、私有 benchmark、原始私人对话或目标仓库。AI 辅助开发过程以文档摘要提供，不冒充完整原始会话。
本次便携交付及启动验证以 Windows x64 为准；附带运行时不能用于 Mac/Linux。
