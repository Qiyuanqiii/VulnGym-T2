> 本页保留修复前 v67 跨项目实验。随后用户已授权修复和 GUI 实现；当前界面、v68 复测及最新请求额度见 [本地工作台记录](t2_web_gui.md)。下面“尚无 GUI”等表述是该历史实验的状态，不覆盖后续进度。

## 结论

当前重做版有 **CLI 命令行入口**，没有 TUI 菜单或 GUI。冻结 v67，在原四个开发案例以外新增 MLflow、NLTK、ONNX 三份公开资料进行真实测试：**3/3 生成完整候选，终态技术错误为 0，19 处源码引用一致**。但内容检查发现 MLflow 的一处条件描述不准确，因此不能写成“3/3 语义正确”。另发现无远端身份的本地仓库走单文件入口时存在身份/修复线索提示不足。

建议先修这两个具体问题，再在同一核心上增加轻量本地 Web GUI，重点改善资料输入和证据复核；不用重做提取系统，也不必先做一套 TUI。GUI 是可用性提升，不是导师新增硬门槛，不会自动提升提取准确性。本轮未实施 GUI 或更改生产代码。

## 本次新发现，不能掩盖

### 1. MLflow：条件描述比源码更窄

实际保存的源码是 `if not gateway_path:`。生成的 critical_operation.desc 写成检查拒绝空字符串，trace 更明确地写成 `Guard rejects only an empty gateway_path.`。这里 GET 使用 request.args，而 POST 使用 request.json；不能把两种输入都限制为字符串。Python 的 `not` 同样对 None、False、0、空列表和空字典成立。免费纯语言反例验证了这一点，没有调用或执行目标项目代码。

主字段位置和代码片段没有伪造，但描述精度仍不足，故该条应进入文字/语义复核，不能仅凭 complete 标为正确。原输出保持不变。后续修复应让条件描述准确保留实际谓词；不能通过把新案例加入答案模板来制造通过。

### 2. 单文件入口：缺失仓库身份时静默少了线索

同一份 NLTK 公告：

| 入口 | repo_url | 修复候选 | 输入状态 |
| --- | --- | --- | --- |
| 本次 JSONL，明确 repo_url | 已识别 | 2 | prepared |
| `--advisory 文件 --repo 本地裸仓库`，不提供映射 | null | 0 | prepared，且没有提示 |
| 单文件 + 明确 repo-map | 已识别 | 2 | 与 JSONL 等价 |

原因是该本地缓存没有可推导的远端身份；单文件入口的仓库信息返回 null 没触发警告，而公告 API 的 source_code_location 当前也没有进入资料归一化的身份字段。随后同仓库 commit 链接筛选因缺少身份而未提供候选。不是 JSON 文件解析失败，也不能据此说模型必然失败；问题是用户看见 prepared，却不知道比 JSONL 少了有效上下文。

没有修改 Git 远端或放宽跨仓库检查。通过现有 repo-map 明确身份后，三个案例的 JSONL、URL 列表及单文件入口在报告身份、仓库 URL、公告正文和修复候选上逐项一致；这些预检查全部 **0 模型请求**。后续宜补齐/确认主公告提供的仓库身份，并对仍然缺失或冲突的情况明确提示，避免静默差异。

## 当前交互与 GUI 的合理范围

当前入口为 `python -m vulngym_t2`，参数选择文件/资料目录/JSONL/缓存 URL 列表，终端输出 JSON 进度，密钥隐藏输入，生成 JSONL 和复核旁车。没有方向键菜单、持久终端面板或网页窗口，因此属于 CLI，不是 TUI/GUI。CLI 的兼容默认配置并不是本次通过的完整显式配置；普通使用者仍需知道较多参数。

建议的第一版 GUI 是绑定本机的轻量网页，只包装同一 CLI/核心：

1. **输入区：** 粘贴资料或来源 URL、选择公告包与已有本地仓库；展示并确认识别出的主公告/仓库身份，缺资料时明确提示。不能把输入“灵活”理解成缺少资料也编造字段。
2. **运行区：** 默认选择已实测配置，显示当前案例、请求已用/剩余及真实阶段；额外参数折叠。API key 仅供本次进程，不写日志、导出或浏览器持久存储。
3. **复核区：** 字段与引用源码并排，显示不确定理由、发生过的纠正和技术失败。标识“完整候选”与“人工确认”分离；本次 MLflow 就说明不能把 complete 渲染为“内容全对”。来源文字当纯文本显示，不执行其中代码。
4. **导出区：** 输出正式 entries/reports，同时保留 review/错误旁车，方便交验和人工接手。

不另建第二条模型链，不因 GUI 自动 clone/fetch 或执行目标代码，不先做一套 TUI 再做 GUI。建议顺序为：修正这次暴露的两处问题并定向验证 → 增加薄 GUI → 扩大公开案例覆盖；不是重新堆一轮与问题无关的门禁。
