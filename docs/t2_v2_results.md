以上是交付者对已保存材料的定性自评，不是独立人工标注。所有完整候选维持 `verify=0`。建议审核者把“字段准确”“入口可达”“关键缺陷”“权限/部署前提”和“同一链路”分别记录，不要只看完整率。

后续保存证据核对发现：Flowise 的 commit 理由将所选父提交误称为修复提交；Langflow 完整路由描述未由引用窗口证实，Flowise 权限说明需区分公告说法与源码独立确认。详见 `docs/t2_case_notes.md`。这些是具体文字/证据边界问题，不把它们推断成所有位置都错或新准确率。旧运行保留原样，勘误单独附上。

## 对照题目

- **资料融合：** 原公告 + 本地候选修复/历史 + 实际源码；不请求答案 API，不读隐藏基准。公开公告本身已有路径或修复信息不等于额外预选答案。
- **代码真实：** 必须引用选定 commit 的实际文件读取，再逐字核对；未知字段不编 SHA、行号或代码。
- **结构化和回改：** 15 字段 schema，配套 reports 聚合；预检错误反馈到既有一次自查，最终仍过字段/源码检查。无法建立的可选 trace 可为 `[]`。
- **不确定性：** 完整候选和草稿分开；草稿 `draft_fields` 保留空值、建议值、原因和引用，不把不完整 JSON 冒充完整 schema 条目。
- **批量：** 真实 GHSA URL 列表 + 缓存 + 本地仓库映射已运行；输入失败可逐条保留，provider 停止则剩余记录明确未处理，不自动重跑。
- **交付：** 源码/README、短设计及三页 PDF、真实 JSONL、逐批中文自评、迭代记录与五分钟现场演示说明。现场答辩由提交者实际展示；未伪造视频或导师验收。

54 项离线功能检查覆盖输入、只读 Git 工具、预算、协议解析、字段保留、预检回改和导出，不能代替上述语义审核。干净解压运行也只证明独立可运行，不证明广泛数据上的效果。

## 已知限制与后续优先级

2026-09-10 目标复核后增补：本地 refs/提交说明查询已接入原模型只读工具循环；新增离线 `pending` 工具核对已处理前缀后生成未开始的 URL 清单，不自动重试。现有真实样例均早于这两项改进，不能用旧 3/3 证明新功能的模型效果。当前目标/勘误与下一步见 `docs/t2_goals.md`。

随后增加离线 `review_export`：从终态 summary、entries、review 生成可读复核包，按 entry_id 关联而非假定行序相同。模型自查提示也补了 desc/reason 的来源层次和提交角色检查，沿用一次自查，不增加调用。导出不改变模型结果，提示效果仍待真实复测；人工审核与演示尚未完成。

1. 先由人工评审当前三个完整候选和 OpenClaw 失败材料，纠正语义错误后再扩大陌生样本范围；不要用多次抽样后的最好结果作盲测成绩。
2. 当前一份公告最多产出一条入口记录；多入口枚举、缺失历史补全及更复杂的跨文件关系仍属扩展工作。
3. 目标仓库和公告需事先在本地可用；程序不 clone/fetch、不执行目标。provider 空白/格式/权限错误会停止批次，失败现场和未处理计数可见。
4. T1 联动、GUI/TUI 和视频制作不是当前核心功能的前置条件。经用户确认，重做版独立发布到私有仓库 `Qiyuanqiii/VulnGym-T2`；旧库和旧历史保留，不迁入新仓库。
