## 本轮实际修复

1. **成稿格式指导**：将运行提示中的伪 JSON 改为由当前序列化器生成的完整、可解析 JSON；明确八字段、合法枚举，以及不确定位置仍须包含完整 `value` 对象。提示版本 `snapshot-guidance-v1`；wire 仍为 `snapshot-v2` / `candidate-serial-snapshot-v2`。不猜补坏 JSON、不放宽 supported、不自动重试。伪 JSON 是确认存在的歧义，不是已经证实的历史失败根因。
2. **上下文计算**：把客户端实际附加的阶段说明计入预算，自查预留也计入其完整提示，避免本地预估低于实际发送大小。
3. **缺失 HEAD 的导航**：在原工具预算内预取一次至多 8 个本地 refs，只提供导航，不自动选定漏洞版本。本轮先导调用错误地传了空 prefix，底层拒绝；现已省略可选参数。新增真实临时 bare Git、缺失 HEAD、非空 remote ref 的集成测试，而不只使用模拟 RepoReader。
4. **理由引用覆盖**：明确的证据 ID/行范围超出实际可见窗口时，对相关字段降为不确定并保留建议与理由；把问题反馈到原有一次自查。含糊自然语言、否定或不确定句仅警告；跨 SHA 只记录比较上下文，原正式位置的 SHA 检查不放宽。没有识别到行号不意味着理由正确，范围覆盖不意味着语义正确。
5. **错误诊断及导出**：只保存白名单解析诊断，不保存原始模型答案或密钥；复核报告可显示解析层和引用问题。额外检查发现 warning/error 展示段误放在验证函数导致未定义 `lines`，已经移回渲染函数，并补保留警告/错误的两个导出端测试。
6. **引用数字边界**：超长末行数字原先可能回退成单行并误标 covered；现按完整数字识别并标非法范围，残缺范围不回退成覆盖。新增超长数字、各分隔符和不完整范围测试。

第 5 项导出位置和第 6 项数字边界是在 OpenClaw 运行结束后修复，随后离线回归；未为这两个确定性修复再次调用模型。原始实测 JSONL 未重算、未覆盖。
