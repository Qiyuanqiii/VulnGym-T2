# 一次粘贴多个 GHSA / OSV 公告链接

## 用户操作

1. 解压产品 ZIP，双击 `start.cmd`，点击“添加资料并提取”。
2. 在默认“粘贴公告链接（GHSA / OSV）”模式的输入框中一次粘贴多个链接，可混合来源。换行、空格和 Markdown 链接均可；同一来源重复公告只处理一次，每批最多 20 条。OSV 页面与 API 的同一编号视为相同来源；GitHub 与 OSV 即使关联同一个 GHSA，也分别保留，不会暗中合并或改变来源。
3. 点击“获取资料并检查”。程序先获取公开公告，再获取公告能够唯一确定的公开源码仓库；不要求填写本地路径、缓存目录或仓库映射。
4. 资料检查结束后，输入自己的模型 key，设置整个批次的请求上限，明确确认后开始提取。检查资料不调用模型；准备成功也不会自动开始付费步骤。
5. 同一批次内查看逐份进度，结束后用“导出数据集”取得 `entries.jsonl`；待补充内容查看复核报告及 `drafts.jsonl`。

可一次粘贴以下三条已见开发案例，不能把它们当作新输入盲测：

```text
https://github.com/advisories/GHSA-f8m6-h2c7-8h9x
https://github.com/advisories/GHSA-f3f2-mcxc-pwjx
https://github.com/advisories/GHSA-8r55-rv5w-6pfm
```

资料准备最多并行两项；之后模型提取逐份执行，共享本批授权，不是同时启动多套付费任务。每份资料最多 12 次模型请求，三份可设置批次上限 36 次；这不是费用金额上限、实际消耗承诺或完整结果数量保证。请在模型服务平台另设费用硬限额。

也可直接选择 OSV 作为公告来源，例如：

```text
https://osv.dev/vulnerability/GHSA-f8m6-h2c7-8h9x
https://osv.dev/vulnerability/GHSA-f3f2-mcxc-pwjx
https://api.osv.dev/v1/vulns/GHSA-8r55-rv5w-6pfm
```

界面按识别的去重链接数建议每条 12 次的本批上限；手动修改过上限后，增删链接不会自动覆盖它。粘贴或检查输入均不会自动启动模型。

## 下载与保存

### 正式联网配置

解压后，双击 `start.cmd` 保留系统默认方式，或双击 `start-direct.cmd` 选择直连。也可给 `launch_workbench.py` 或 `python -m vulngym_t2.web` 传 `--network-mode system|direct`。默认值为 `system`，非法取值不会启动。网页 `/api/state` 与界面展示本次选择，下载回执记录 `network_mode`。

直连模式为公告 HTTP 显式创建不使用代理的连接，并仅对 Git 下载子进程去除代理环境/配置；没有修改 Windows 注册表或全局进程环境，不影响模型传输、用量文件、key、逐批确认。它不会因失败而自动切换到另一种模式。成功的资料缓存仍可跨启动复用，回执中的 cached 标志会区分复用和实际下载。

要切换，请先等当前任务结束，关闭该工作台启动窗口，再启动另一种模式；不在批次中途热切换。

该配置的离线回归共 126 项 Python 检查、49 项网页逻辑检查通过，覆盖默认/直连启动、已有用量配置与只读兼容、下载参数传递、HTTP 代理选择、Git 子进程配置及失败不切换模式。真实浏览器已确认直连启动时显示“当前资料联网：直连”；本轮没有请求模型，先前单条真实提取的 9 次请求不计为本次测试。

### 访问与容量限制

- 需要按所选公告来源联网访问 GitHub 或 OSV；相关源码仓库仍从 GitHub 获取，系统 Git 必须在 PATH。仓库以完整 bare Git 形式下载，可能明显大于公告文件；不安装目标项目依赖，不运行目标代码。
- 下载限制为单仓库最多 2 GiB、下载缓存累计最多 6 GiB、单次仓库 clone 限时 300 秒，公告 HTTP 超时为 30 秒；超出限制会停止并保留失败信息，不能承诺任何大小的仓库均可自动准备。
- GitHub 链接的公告获取使用 GitHub 的公开接口，见 [Get a global security advisory](https://docs.github.com/en/rest/security-advisories/global-advisories#get-a-global-security-advisory)；OSV 链接使用 [OSV API](https://google.github.io/osv.dev/api/)，只请求 `https://api.osv.dev/v1/vulns/<ID>`。仓库来源必须明确，不能凭模型猜一个项目继续。
- OSV 链接独立选择 OSV 公开接口，不会因 GitHub 403 自动改走 OSV。OSV 原始 JSON 单独缓存，原始输入网址、来源提供方和来源编号保留；正式输出 `source_link` 只使用公告明确关联的唯一 GHSA。公告必须明确包含 GitHub reviewed 状态，才能满足当前题目固定的 `origin` 要求；不明状态、已撤回、无唯一 GHSA 或无明确仓库的记录会保留为输入问题，不伪造来源。
- 下载内容保存在解压目录的 `data/downloads`，成功缓存可复用，不放进用户 C 盘临时缓存，也不自动清理。请将产品解压到有足够空间的位置；如果解压目录本身位于 C 盘，数据仍会占用 C 盘。
- GitHub / OSV 限流、拒绝访问、网络错误、大仓库超时、无明确仓库或所需历史不完整会保留为输入问题。不会轮换 IP、自动重试或自动切换公告来源。失败项不能显示为成功提取，缺失字段不自动补齐。
- 原来的“正文/文件”和“本地批次文件”方式继续离线工作；本地 URL 文件仍需要公告缓存和仓库映射。直接粘贴链接应使用新的链接模式，不要贴进“批次文件路径”。

## 与题面及模型的关系

题面原本还说明出题方提供本地公告缓存与已 clone 仓库；新模式解决用户希望“只粘贴链接也能准备输入”的操作需求。自动获取资料不意味着任何 GHSA / OSV 公告都有足够信息，亦不免除版本、真实代码位置及引用核对。仅有 OSV 编号、无法唯一映射到 GHSA 的公告暂不能按这份题目的输出格式提取，这属于当前数据契约边界，不是下载成功即代表完成。

本次只扩展资料入口，不改变模型及 `snapshot-guidance-v85` 标注协议，不接入 T1 自动反馈。完整候选、合理不确定和技术失败继续分别记录；`verify=0`，不是人工审核通过。可选 trace 不被强行补齐，批量结束也不保证每份资料都有完整条目。
