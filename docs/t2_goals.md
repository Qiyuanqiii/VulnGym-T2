# T2 目标与交验边界

主目标是 T2：从公告与仓库提取有多源依据的条目，不确定时保留待审；不含独立 T1 自动反馈。不以完整数代替质量验收。新增用户交互目标是“一次粘贴多条 GitHub GHSA / OSV 链接，自动准备公开资料，再统一确认模型提取”，详见 [URL 批次说明](t2_url_batch_20260914.md)。既有提取质量证据见[代表性验证](t2_representative_validation_20260913.md)。

## 当前输入与交付范围

正式启动配置提供系统默认（`start.cmd`）与直连（`start-direct.cmd`）两种明确选项；工作台显示所选下载方式。只影响公开资料下载，不修改系统网络、不自动切换出口，不改变模型连接、预算、标注规则或自查要求。

默认 Web 入口接受最多 20 条去重后的 GitHub GHSA / OSV 链接，支持换行、空格及 Markdown 链接。用户不必先手工下载公告、clone 仓库或编写缓存映射。程序获取公开公告，在仓库来源唯一明确时下载公开 Git 历史；最多两份资料并行准备，随后以一个共享预算的批次逐份提取。准备资料与模型提取是两个阶段，未确认 key、批次上限和授权前不调用模型。

OSV 页与其 API 链接按同一 OSV ID 去重，GitHub 与 OSV 两种来源不暗中合并；原始 OSV 数据和输入来源留存。正式输出目前仍要求唯一真实 GHSA，且 OSV 明确标记 GitHub 已审核；无对应 GHSA、多个冲突编号、未审核或已撤回时停止该项准备，不伪造固定来源字段。仓库克隆仍可能访问 GitHub；接入 OSV 不等于消除所有 GitHub 网络依赖。限流或权限拒绝不触发 IP 池、凭据轮换或换来源重试。

题面原资料包除必有 GHSA URL 外，还描述了出题方提供公告缓存与已 clone 仓库；“只有 URL 也能操作”是用户现在明确要求的产品入口扩展，不把过去离线输入能力冒称为已经完成此扩展。导师关于输入不应有固定格式的说明不免除证据要求：下载失败、仓库不明确或版本缺失必须明确报告，不能编造或自动放宽完整候选标准。

本地正文/文件与本地批次模式保留离线使用，不运行目标代码。模型、标注协议 `snapshot-guidance-v85`、正式输出字段与 `verify=0` 不因下载入口改变。新增入口的验证结果单独记录；旧批次成绩不能证明其成功。

## 先前修复轮次范围与完成方式（历史）

主目标是输入公开公告及已准备的本地 Git 仓库，自主读取相关历史和源码，交出可复核字段、真实草稿、运行限制与操作说明。独立 T1 自动反馈排除；不执行目标代码，不读取禁区，不借旧工作区继续写入，不在本轮创建 ZIP、推送或把额外付费作为前置门槛。六小时是本次推进时间授权，不是准确率承诺。

收尾顺序为：修正已经证实的协议/预算/展示问题；用离线检查确认边界；对既有真实结果作有界内容复核；统一交付说明及仍未解决的问题。当前修正完成与否以实际验证为准，不能仅靠时间到点或文档齐全宣布全部效果完成。

## 已纠正的理解

| 项目 | 本项目采用的解释 |
|---|---|
| 两题关系 | T2 为主；题面 T1 联动原为扩展，本轮已明确排除，未接入独立 T1 自动反馈。 |
| 固定测试集、排行榜、70 题 | 导师取消了固定样例打榜思路；可自选公开案例，但要如实解释选样、失败和局限。 |
| 50/80/100 分、F1 和幻觉率阈值 | 题上明确为示例/参考，不把这些数值自设为导师硬门槛，也不凭小样本宣称已达到。 |
| EP/CO 各占半分、统一 ±5 行、固定 return 模板 | 已被勘误，不能继续作为标准答案规则；需结合版本、调用关系和机制解释。 |
| trace、T1、GUI/TUI | 非空 trace 可选；本轮不含 T1 自动反馈。产品现有 CLI + Web，GUI 为用户后续明确要求，不是原题指定界面；没有 TUI。 |
| 不确定结果 | 导师及用户都强调宁可保留不确定，也不要错标；有用部分仍应保留。 |
| 过程证据 | 不仅交结果；应说明 prompt、问题、改动、验证与取舍。开发摘要不是完整原始会话，需诚实区分。 |

## 产品契约

- 默认 Web 链接模式自动获取公开 GitHub / OSV 公告与唯一明确的公开仓库；本地模式仍接受公告正文、JSON/JSONL、公开 patch、自然文本、URL 列表文件与已有仓库。CLI 的 Markdown 正文用 `--advisory`，本地 URL/JSONL 列表用 `--input`；它们不自动 clone/fetch。不要求用户预选答案文件或漏洞行号。
- Web 默认 low、多候选模式；CLI 的多候选使用 `--multi-entry --response-mode staged_tool`，共享输入预算并逐候选记录初稿、自审与失败。已运行的 low 配置可保持 thinking enabled，不把旧 disabled 示例当作唯一支持方式。
- 完整候选进入 `entries.jsonl`，规范报告与冲突另存；正式 15 字段和 `verify=0` 不变。完整状态不是人工确认。
- 未确定字段保留在 `review.jsonl`；`drafts.jsonl` 按题面空字符串/空数组投影真实 draft_fields，不回填建议、被拒对象或虚构位置，也不降低完整 schema。
- 输入数、候选数、草稿数和共享费用分别统计；同一编码失败及后果可能出现在多个错误字段，不相加成独立故障。技术失败与合理不确定分开。
- 同模型自查不替代独立 T1 或人类复核；无效/未完成自查不能因已有初稿就升 complete。历史缺失不默认选 HEAD、父提交或补齐 trace。
- 多候选 assessed 模式在预算足够时，为整个输入共享预留一次编码纠正；不提高总 HTTP 上限，未使用不补花。可能因此少选候选，`omitted_count` 如实记录，不算已运行或语义失败。
- 可选 CLI [`--review-read-cycles 0..2`](t2_review_gap_loop.md) 默认 0，非零仅限 staged_tool，GUI 仍为 0。首次完整自审后的真实必要缺口可触发一次定向读决策，只有新增成功回执才重新完整自审；共用原模型、工具和账本上限，可能以少选候选换取输入级循环余量，不保证每槽都有机会。
- 必需字段的 supported 状态若与其自身必要关系说明出现已识别的矛盾，保留待核；这只是有限一致性检查，不是完整语义验证。单独缺少可选 trace 不否定独立成立的入口与关键操作。
