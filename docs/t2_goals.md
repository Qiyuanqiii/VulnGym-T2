# T2 当前目标、验收边界与推进顺序

更新：2026-09-10。此文是新仓库的工作参考，不是导师已签署的验收结论。

## 依据与主目标

依据用户最新补发的带红色勘误 T2 考题截图、原 PDF 的 T2 第 6–10 页，以及此前导师会议转写。截图和会议用于理解要求；不把私人会议全文、密钥或其他会话搬入仓库。

**主交验方向是 T2：输入公开公告材料及已提供的本地 Git 仓库，由系统自主读公告、查历史和源码，产出有依据的 VulnGym 记录；不能确定的字段明确留给人工复核。** 用户登记 T2，因此先把 T2 做好做精，T1 仅为后续可选扩展。

核心价值是减少人工查资料和填表的时间，并让人能判断哪些可信、哪些仍需调查。不能用“JSON 完整”“schema 合格”“代码逐字相同”偷换“语义正确”。也不能为了完整率把推测字段说成事实。

## 已纠正的理解

| 项目 | 本项目采用的解释 |
|---|---|
| 两题关系 | 不要求 T1×T2 都做好才交验；T2 为主，T1 联动是扩展。 |
| 固定测试集、排行榜、70 题 | 导师取消了固定样例打榜思路；可自选公开案例，但要如实解释选样、失败和局限。 |
| 50/80/100 分、F1 和幻觉率阈值 | 题上明确为示例/参考，不把这些数值自设为导师硬门槛，也不凭小样本宣称已达到。 |
| EP/CO 各占半分、统一 ±5 行、固定 return 模板 | 已被勘误，不能继续作为标准答案规则；需结合版本、调用关系和机制解释。 |
| trace、T1、GUI/TUI | 非空 trace 和 T1 为加分扩展；未要求 GUI/TUI。现阶段 CLI 是可接受的实现选择，而非导师指定界面。 |
| 不确定结果 | 导师及用户都强调宁可保留不确定，也不要错标；有用部分仍应保留。 |
| 过程证据 | 不仅交结果；应说明 prompt、问题、改动、验证与取舍。开发摘要不是完整原始会话，需诚实区分。 |

## 当前产品契约

- 输入：GHSA 来源、缓存公告及已有本地仓库；可补充 CVE、公开说明、patch 和提交候选。用户不必预选源码文件/候选编号/答案位置。程序不负责 clone/fetch。
- 处理：有界模型读工具循环，形成逐字段判断，实际字段/源码预检反馈给一次自查，最后导出。历史不足时保留未知，不默认选 HEAD 或修复父提交。
- 完整候选：`entries.jsonl` / `reports.jsonl`，按现有 SCHEMA 导出，自动 `verify=0`。
- 不完整内容：`review.jsonl` 保留 `draft_fields`、建议值、引用、疑点和错误；不是完整 schema 条目，不计入完整数。
- 题面写空字符串/空数组表示 missing；本实现内部复核草稿用 `null`，可选 trace 用 `[]`。这是为避免无效 SHA/坐标进入完整条目的表示选择，不声称导师指定必须采用这种拆分。交验时展示它如何保留信息。
- 失败：已完成的结果不改写；停止原因、未处理数明确可见，不把停止当成功，也不自动更换账号或重试。

## 验收时展示什么

| 要展示的能力 | 已有证据 | 仍然欠缺/不能宣称 |
|---|---|---|
| 输入资料后自主找源码并填表 | 实际公告、Git 读取动作、草稿/自查和 JSONL | 目前大多是有修复线索的已见开发案例，代表性不足。 |
| 来源、版本、位置可检查 | 历史三个候选及本次 V4.1 完整材料两条候选保留字段与证据；新两条各 15 字段且 entries/review 对应一致；减线索 Flowise 另有完整候选 | 重复案例不是新样本；字段对应和字节一致不证明版本受影响、入口可达或缺陷判断正确。 |
| 不确定时保留有用部分 | 本次 Open WebUI、OpenClaw 的无效 JSON 草稿；减线索 Langflow 在传输失败后保留 commit/EP/CO uncertain、其余 12 字段 supported（含空 trace） | 失败草稿不算端到端成功；supported 不是人工认可，不能用其他批次完整结果回填。 |
| 批量可用、停止透明 | URL 批次、逐条落盘、未处理计数；新离线清单已在旧失败样例得到精确的三个未开始 URL | 不是运行中 checkpoint 恢复，也不汇总更晚其他批次。 |
| 自我评估与改进 | 真实自评、失败、用量和开发迭代记录 | 仍需人查看具体语义并记录认可/不认可的理由，暂无独立准确率。 |
| 可交付、可演示 | 私有源码库、README、三页设计 PDF、JSONL、自评、五分钟演示指南 | 尚未录制实际演示视频，也未进行导师现场答辩。 |

本次明确使用 `--model deepseek-flash`（2026-09-10 官方 V4.1 Flash）。完整材料首批 `full-run-01` 为 4 请求输入 / 3 已处理 / 2 完整候选 / 1 草稿 / 1 未开始，18 次 HTTP、239,679 tokens、150.486 秒；仅处理未开始 OpenClaw 的 `remaining-run-02` 为 1 已处理 / 0 完整候选 / 1 草稿，2 次 HTTP、19,875 tokens、4.712 秒。两批均因响应正文为无效 JSON 停止，分别归档至 `examples/run-04`、`run-05`。

减线索首批 `reduced-run-03` 请求 2 份、处理 Langflow 1 份，0 完整 / 1 草稿 / 1 未开始；11 次 HTTP、108,308 已报告 tokens、91.337 秒，因读取响应正文的传输失败停止。其后 `reduced-remaining-run-04` 仅处理未开始的 Flowise，1 完整 / 0 草稿、10 次 HTTP、64,603 tokens、34.354 秒，正常 completed；分别归档至 `examples/run-06`、`run-07`。失败回执不是拒绝或权限失败，后续项处理不是自动重试。

因此完整材料 4 份为 2 complete / 2 draft，减线索 2 份为 1 complete / 1 draft；两套重叠使用既有 4 个案例，独立新样本 0。同一授权账本累计 41 次模型请求，另有目录查询 1 次，共 42/500；432,465 是已报告 token，另有 1 次请求用量未知，不能宣称精确总量。此次已停止使用临时 key，可撤销。详细证据和限制见 [V4.1 实跑记录](t2_v41_results.md)。

旧 `examples/run-03` 的 3/3、18 次 HTTP、525.471 秒是历史开发记录，不是本次结果或总体准确率；旧空白响应失败也原样保留。本次虽在提交角色与说明来源层次上有改善，仍发生协议失败，核心尚未达到广泛效果验收。

此前离线功能增补阶段通过了 44 项针对性检查（含 13 项历史工具检查）；当时 Langflow 材料库可列出 2 个 refs，并从显式起点取得 3 条有界历史命中。该材料库没有有效 HEAD，因而补充了先列 refs、再显式选择搜索起点的提示及检查。那一阶段没有模型 HTTP 请求；这是历史功能证据，不能继续表述为本轮零请求。本次 V4.1 保存记录已包含新工具调用，但仍不足以证明陌生样本或缺修复线索场景的效果。

## 推进顺序

上述为 run-01 至 run-07 的历史阶段。用户再次确认后，已做严格协议真实定向复测，归档 run-08/run-09：共四项已处理，1机器完整候选（仍有入口/版本声明疑点）、1证据不足草稿、2技术失败草稿。默认 thinking+auto 可返回普通 stop；新增显式 `--thinking disabled` 配合 required 可强制函数调用，但仍实际出现函数参数 JSON 语法错误，不能说格式故障已消除。累计61/500请求，已报告656,871tokens，另有此前一次用量未知；本轮模型调用已结束。

接下来优先修短输出协议可靠性及“入口已建立”和“仅看到内部调用片段”的语义区分，同时检查是否因缺少修复/版本表而过度弃答。先解释当前候选与草稿的真实质量，再补少量新样本，不继续反复跑同四题挑最好成绩，也不新增一套大规模门禁。完整记录见 `docs/t2_v41_results.md` 末节。

1. **收束本次真实运行：** 本地 refs/提交说明查询、离线未开始 URL 清单和复核包导出已加入实现。本次新模型完整材料及减线索实验均已结束；保留格式失败、传输失败、成功记录与未知用量，不隐藏失败或把不同批次的最好结果拼成一次成功。
2. **补足效果证据：** 当前仍是已见开发公告。在后续明确授权范围内，才扩展少量有代表性的非 Linux 公开材料并包含线索不全场景；事先记录输入与预算，不调用已知答案接口。新工具参与实跑不等于已经证明广泛效果。
3. **人工语义复核：** 查看完整候选和草稿各自的证据，记录版本、入口、关键操作、二者关系及权限/部署前提哪些得到支持，哪些仍未知；允许多种有依据的合理位置，不套唯一金标。旧问题见 `docs/t2_case_notes.md`，本次提交角色与来源限定的改善及仍不清楚的措辞见 `docs/t2_v41_results.md`。这些是助手对保存材料的核对，人工签字仍未完成。
4. **最终展示：** 按实际运行做五分钟视频或现场答辩，展示一个完整候选、一个不确定/失败例子，以及一次真实问题如何推动改进。当前指南不是已经完成的视频。

继续开发仅在新仓库；旧库/旧 finalizer 不作为当前门槛。没有新的模型授权就继续做可离线完成的工作，不复用已通知用户可撤销的临时 key。后续每一轮更新“做了什么、实际证据、尚未验证什么”，不报无法解释的整体百分比。
