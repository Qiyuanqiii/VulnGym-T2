## 本轮具体修复

- 请求软件上限支持用户明确追加的 1000 次授权；沿用原账本，999 次生成 + 已用 1 次目录查询，不重置历史。
- 中途无损整理重复上下文，保留全部证据与候选状态，使仍在原预算内的注册源码补读可继续。
- 对版本仍未知、已有另一个成功检查的 SHA 和真实源码名称的条目，至多补一次限定路径的另一版本声明搜索与源码读取。不猜 SHA、不沿用另一版本坐标、不自动判定版本。
- 支持已读且已选区间内的完整单行 Python 装饰器导航，仍保留范围、缩进、工具和上下文边界。
- trace 必须考虑中间过滤、赋值和分支，不能把同函数的非相邻语句说成连续，也不能声称过滤后的值未经修改。
- v29 把粗分类不强求 CWE 的规则直接放到该字段；把函数和条件分支的作用域判断放到 commit/CO 字段旁。没有输入专用答案、硬编码坐标或自动升级状态。
- v30 新增显式 `assessed_tool`：每份初稿与自查先做一次有推理的简短证据判读，再做一次关闭推理的 required 原生函数填表。判读仅保存公开回答，不保存隐藏推理；不是源码证据，不允许执行操作或自动认可字段。两次 HTTP 均计原账本和每题调用上限；先保留原必需自查，多条也按每候选四次初稿/自查请求分配。不能启动完整两步时，不先花一次判读请求。
- v31 在此显式模式的 EP/CO/trace 位置对象中用 `source_id` 表示单个已保存源码编号，理由引用继续用 `evidence_refs` 数组。先严格验证新接口，再确定性映射回原内部引用结构；不选择重复键、不接受混用旧键/新键、数组冒充单值或缺字段。旧接口不自动接受新接口，最终数据集及证据存储不改名。判读/填表两步没有额外增加。
