# VulnGym T2：资料提取与复核工作台

设计版本：snapshot-guidance-v84 · 2026-09-14。当前实现说明；v83 三批与 v84 NLTK 已真实运行，完整候选仍未经人工批准。

## 目标与用户操作

把公告与已有本地仓库交给系统，由模型寻找相关版本、入口和关键操作，产出可复核的 VulnGym 记录。用户不必预选答案文件或行号。主做 T2；独立 T1 反馈自动迭代按用户要求排除。拿不准应保留有用字段与依据，不能编造缺失内容。

产品为 CLI + 轻量本地 Web，不是 TUI。操作顺序为：添加资料、免费检查、确认预算、开始提取、逐条查看、导出。支持正文、JSON/JSONL、patch 和带缓存/仓库映射的 URL 列表；PDF/图片需先转文本。Web 只监听本机，不执行目标程序或自动 clone/fetch。

## 架构与职责

```text
公告 / JSONL / 缓存 URL 列表 + 已有 Git 仓库
                  ↓ intake / cli / web
pipeline：规划读取 → 候选拆分 → 初稿 → 预检/补读 → 自查
           ↕ repository        ↕ llm / transport
output：来源、字段状态、同版本源码及 schema 核验
                  ↓
完整 entries / reports；草稿 drafts；过程 review / actions / summary
```

| 模块组 | 责任 |
|---|---|
| 输入与交互 | 识别公告身份、材料与仓库；本地任务、状态和下载。 |
| 读取与判断 | 模型选择线索；程序执行有界 Git 工具并保存实际出处。 |
| 协议与预算 | 分离文字评估和结构化编码，共享请求账本及停止条件。 |
| 校验与产物 | 核验引用和源码位置，分开完整条目、草稿与技术失败。 |

运行清单为 43 个文件：30 个产品 Python、5 个 vendored Python、8 个 Web 资产。运行只依赖 Python 标准库与 Git，不导入旧工程；界面使用原生 HTML/CSS/JavaScript、本地字体和项目图标，无远程 CDN。

## 输出契约

完整 entries 使用 schema 的 15 字段，固定 `verify=0`；reports 只聚合完整候选。草稿也保留 15 个字段名，未知标量/位置为 `""`，数组为 `[]`。原建议、理由、出处和异常留在 review，不把建议或被拒编码偷偷填回结果。完整、坐标匹配和自查完成都不等于人工批准。

## 工具与提示词

七类只读 Git 能力为 `inspect_commit`、`list_files`、`search_code`、`read_diff`、`read_file`、`list_refs`、`search_history`。公告、源码和提交说明是资料，不拥有指令权限。没有 fix 时可沿已有 refs/历史查找；命中、HEAD、父提交都只是线索，不自动成为受影响版本。

固定字段规则、阶段指令和真实资料分开传入。代表性配置为 `staged_tool + assessed_tool + plan_tool`：规划读取后，每份初稿/最终自查各用一次文字评估、一次结构化编码。默认单条；显式多候选共享输入预算，最多选四项。后来才读到的证据不能倒灌到此前调用记录。

字段判断附状态、短理由与现有引用。提示要求区分外部入口与内部 helper，读清实际转换和消费者；声明/配置不是每次运行的后续步骤，生成器创建也不是消费。必要关系未知时保留不确定；可选 trace 可以为空。源码机制与发布范围映射分别陈述。

## 读取、纠正与自查

初稿先做本地结构/引用检查，再安排预算内补读和一次最终自查。实际展示的工具结果和截断均有记录。失败不变成支持证据；不自动重试 HTTP、不切换账户，也不借新账本重置用量。

- **候选预读：** 仅用当前候选引用的已知差异路径/SHA 排序；按明确提到的文件名分组，保留同名防串。唯一未读目标才读取，歧义时交回正常规划。
- **函数体续读：** 从同版本、连续无冲突的引用窗口识别已出现调用的 Python 函数，建议紧接末尾的最多 40 行。每次只读一窗，共用每输入两次尝试上限，不增加模型调用或批准字段。
- **编码预算：** 多候选 assessed 输入在额度充足时共享预留一次编码纠正，保留后续初稿与自查额度。可能少选候选，未用预留不强行消费。被拒对象整份不用，只做一次受限重新编码。
- **必要前提：** 有限规则检查当前字段“声称连接已显示，却明确承认对象身份仅推断未读”的矛盾；不跨字段传播。公告、docstring 与源码可以互证，不要求运行对象全部独立验证；未命中也不证明语义正确。
- **上下文：** 冗余搜索/历史可无损表格化，保留源码、顺序、出处和限制；已规划源码允许较小整行窗口。最终自查预留与 100000 字符总上限不提高。

历史生成账本不改。总授权 3000 次包含一次历史查询，执行时生成上限为 2999；每批另有限额。资料进度、候选结果和实际请求分别计数，未选候选不计作已处理或已证实的问题。

## 怎样检查结果

控制器持有来源身份、固定 origin/verify。非空位置必须对应选定 commit 下成功读取的真实代码，再由仓库读取器核对。公告、搜索命中或 patch 引用本身不足。行号仅在已读同提交/路径窗口中、逐字片段唯一匹配时纠正；不改代码或语义状态，窗口外及歧义不予补造。

Schema 检查格式，源码检查字节，模型自查重新判断字段；都不能证明所有语义。人工仍需看版本依据、入口角色、实际操作、必要调用/类型/配置条件、trace 顺序和候选独立性。逐字段保留问题，不用总分掩盖。

## 已有证据与当前缺口

## 踩坑、取舍与交付

旧接口把模型困在预选范围，整体成败式输出又丢失有用字段；重建后让模型自主找证据，把限制放在工具权限和逐字段判断。测试暴露了空响应、非法编码、恢复预算不足、helper 遮住操作、正确引用配错误解释。应逐机制修复并保留失败，不反复重跑换取好看的完整数。

交付包含源码/README、版本化 prompt、真实 JSONL、自评和迭代说明。开发摘要与精选对话摘录不是完整会话或隐藏推理。五分钟演示指南可用于现场讲解，不是已录制视频。T1 联动排除，不强凑 trace；本轮不新建用户 ZIP，不宣称导师认可。

操作见 README、工作台及演示指南；事实与限制见 `docs/t2_representative_validation_20260913.md`，协作过程见 `docs/t2_v2_iteration_history.md`。旧 PDF 保留历史身份，本说明单独生成 v84 版本。
