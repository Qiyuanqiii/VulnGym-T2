# T2 轻量本地工作台

本地工作台用于添加资料、查看结果和导出，与 CLI 共用提取逻辑。默认输入方式为“粘贴 GHSA 链接（自动获取资料）”：一次粘贴多个链接，自动准备公开公告与可明确识别的公开仓库，再确认模型用量。新增入口的验证范围见 [URL 批次说明](t2_url_batch_20260914.md)，既有提取质量与历史测试见[代表性验证](t2_representative_validation_20260913.md)。

技术栈为 Python 标准库服务与原生 HTML/CSS/JavaScript，监听 127.0.0.1。GUI 当前使用 low、多候选和 `snapshot-guidance-v85`；本次链接输入扩展不改变模型或标注协议。已有结果可离线查看、导出，不需要为回放新增付费请求。下文历史区中的 v84/high 配置、旧额度和核验地址仅记录当时情况。

## 启动

完整解压产品 ZIP 后双击 `start.cmd`，浏览器自动打开本机工作台；无需手填账本或命令行设置。`start-extraction.cmd` 打开同一个完整工作台，`start-demo.cmd` 是明确的只读回放。启动本身不调用模型；新使用者在网页中输入自己的 key、批次上限并确认后，才会开始提取。用量配置自动保存在本机用户目录，下载资料在包内 `data/downloads`，输入与结果在包内 `data/runs`。详见根目录 [启动说明](../README_START.md)。

## 高级 CLI 启动与历史授权说明

以下仅供已有工程环境的 CLI 操作者追溯，不是老师或新使用者的启动步骤。本任务曾使用的授权组合为 `--authorization-limit 3000 --effective-request-limit 2999 --historical-requests 1`：历史账本 limit 为 3000，执行期累计生成最多 2999，加历史 1 次使界面总上限为 3000。固定授权 CLI 参数不是单批请求数，不能重置用量。下面 500 示例仅适用于其自身批准额度。


## 工作流

1. 点击左侧“添加资料并提取”。默认选择“粘贴 GHSA 链接（自动获取资料）”，在多行框一次粘贴链接；支持空格、换行与 Markdown 链接，自动去重，最多 20 条。不需要为不同项目逐个提交。
2. 点击“获取资料并检查”。此动作会联网下载公开公告与唯一可确定的公开 Git 仓库，最多两项并行准备；不填仓库路径、缓存或映射。下载保留在包内 `data/downloads` 并复用。系统 Git、网络与足够磁盘空间是前提；限流、超时或来源不明确会显示问题，不运行目标程序。
3. 仍可切换为本地正文/文件或已有批次文件，保持离线。正文与文件合计最多 8 份，每份最多 256 KB；不支持直接上传 PDF/图片。已有 JSONL/URL 列表要填本地文件绝对路径，URL 列表需要已有公告缓存和仓库映射。这些模式中的“本地源码仓库路径”是 Git 仓库目录，不能填写 `record.jsonl`。
4. 输入检查不读取 key、不调用模型。检查完成后输入临时 key，设置整个批次的请求上限并明确确认才开始。资料、路径或上限改变后需重新检查/确认，不会自动启动旧输入。固定使用 staged_tool + assessed_tool + plan_tool / low / 多候选 / 32K / 每份资料最多 12 次请求、64 次本地工具调用，批次默认上限 12 次；多输入共享上限，模型提取逐份执行。没有 HTTP 自动重试；格式错误停止，未处理数量如实记录。
5. 页面显示累计额度、逐条进度和最多 60 条内存事件。页面正常每 2 秒读本地状态，隐藏页面每 10 秒；服务不写轮询日志。刷新页面不会重启任务。
6. “当前条目完成后停止”允许正在处理的条目完成和落盘，再停止未开始的输入。它不是立即取消单个请求；停止后未处理数量单独记录。关闭网页不会停止后台，关闭服务或电脑前请先停止并等其结束。终端 Ctrl+C 也会先等待当前操作完成。
7. 左侧选择批次、搜索项目或公告编号、按状态筛选；右侧逐条查看八个模型字段、原始代码、理由和证据引用。点击依据跳转后，可用顶部“返回字段”回到原处。顶部“导出数据集”“复核报告”和“更多文件”导出批次原文件；9 月 13 日起的新结果另有“导出待补充条目”（`drafts.jsonl`）。旧批次不显示不存在的新文件；不创建 ZIP、不重写原结果。

## 结果含义与限制

- 界面“字段已齐 · 待确认”对应原始结果中的 `complete`（完整候选），只表示满足当前结构、证据引用和流程规则，不代表结论全部正确；`verify=0`，不冒充人工复核。
- “信息不全 · 待补充”对应 `draft`（草稿），保留缺失、不确定及冲突。技术失败与合理不确定依然分别记录在原 `review.jsonl` / `summary.json`。
- 新增 `drafts.jsonl` 使用正式的 15 个字段名：未确定的标量/位置为 `""`，数组为 `[]`，`verify=0`。这是题面 missing 表示的复核导出，不是符合完整 schema 的数据集；完整候选仍只导出到 `entries.jsonl`。原始 `review.jsonl` 中的空值、依据及建议不变。输入失败占位也保留一行，并在报告中单独标识。
- 当前交付接口仅为 CLI 与本地 Web；同模型自查不是独立 T1，也不是人工审核。演示指南是操作说明，另有[五分钟字幕回放](../output/demo-replay-20260914/README.md)，它是保存结果的真实截图编排，不是连续操作录屏或现场新提取。
- Key 只经本地请求体与子进程 stdin 管道传递，不写文件、命令行、环境变量、服务日志或浏览器存储。输入框提交时清空；这不等于操作系统级内存擦除保证。
- 服务通过精确 loopback Host、同源检查、每次启动的会话 token、固定静态文件/结果文件白名单限制访问。它是可信本机单用户工具，不是面向不可信用户的生产 Web 服务。
- 只预览已退出批次或启动时指定的旧结果，不读取运行中输出。网页结果预览每个文件最多 32 MB，下载最多 64 MB，超大结果在本地用 CLI 处理。
- 本次启动的输入资料与结果保存在指定 runs-root，不会自动删除。服务重启后，用 `--review-dir` 指向旧 output 查看；不自动恢复或重跑未完批次。
- 界面使用清晰层级、即时反馈、键盘焦点和 reduced-motion 支持；没有复杂动画、远程字体、第三方 JS 或追踪组件。
